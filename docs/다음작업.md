   모의기 빔 모델(`(2Δaz/폭)² + (2Δel/폭)² ≤ 1`)과 실제 연동에서 미탐 직전 값 분포를 보고 정한다.

   빔 안 위치 그래프는 뺐다(사용자 결정, 잔차와 같은 정보). 빔 안 위치는 상태 줄 막대로만 본다.

## 2. 문제 자동 기록 후속 (`core/problems.py`)

- **실제 데이터로 검증**: 가짜 처리부에서는 미탐·트랙 종료·빠진 빔·연결 끊김·재시작만 확인했다. 실제 연동에서
  - 탐색 프레임 시간·추적 주기가 트랙 생성·삭제 순간 잠깐 기준을 벗어나 문제가 너무 많이 잡히는지
  - 확인 실패(오경보)가 잦아 목록을 덮는지 → 수준을 낮추거나 기본 거르기에서 뺄지
  - 묶는 시간(`MERGE_MS` 2초)이 맞는지
- **빔 안 위치 조기 경보**: '빔 밖 탐지'는 모니터 연관 추정에 기대 자동 기록에서 뺐다(PR 리뷰). 빔 안 위치는 추적 탭 상태 줄에서
  보는 값으로 쓰고, 주의 기준은 1장 '정해야 할 것' 1번에서 정한다. 자동 기록에 다시 넣으려면 연관과 무관한 조건이어야 한다.
- **처리부 로그 문제의 녹화 위치**: 로그는 처리부 시각만 있어, 로그 실행 수 = 녹화 구간 수일 때만 순서대로 짝짓는다(추정).
  로그 파일 이름의 실행 시각(벽시계)과 녹화의 수신 시각으로 맞추면 정확해질 것으로 추측.
- **긴 녹화 성능**: 40초 녹화 0.2초 → 10분 약 3초(추정). 수십 분이면 여는 시간이 길어지므로 백그라운드 계산이나 진행 표시 검토.
- **통계 요약 연계**: 통계 표에 '자동 기록 문제' 항목(종류별 건수)을 더할지.
- **실시간 기록 보존**: 지금 실시간 문제는 메모리에만 있고, 녹화를 열면 다시 계산한다. 녹화하지 않은 구간의 문제를
  목록으로라도 남길지(파일 저장) 검토.
